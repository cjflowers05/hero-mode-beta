# Hero UI Kit v1 — first, second + third pass (2026-07-29)

Experimental visual upgrade, isolated in `future/` so `Current/` (the shippable app) stays untouched. Built from a reference sheet the user provided (`new_art.png`), using **Option 3**: extract neutral/structural chrome, keep all color/glow driven by CSS so it still re-themes across all 15 hero themes.

## The one real gotcha hit during this pass

The source button art has **text baked into the bitmap** ("TACTICAL"). The first attempt used `border-image-slice: … fill`, which stretches a thin *middle* strip of the source to fill variable-width buttons — that middle strip contained letter fragments, so buttons rendered with ghostly stretched text bleeding through behind the real label (e.g. "SAVE MY WEEK" over a smeared "ACTICA"). Fixed by dropping `fill` entirely: only the two end-cap regions (which are clean ornament, no text) render from the bitmap; the stretchy middle is a plain CSS gradient instead. **If more assets get pulled from this sheet, check for baked-in text/numbers before using `fill`-stretch — anything in section 2 (buttons) and arguably the "31" calendar icon in section 1 has this problem.**

## Deliberately deferred (not in any pass)

- **Hero cards & background scenes** (sheet sections 4, 7) — each is postage-stamp resolution *inside* the reference sheet; using them for real needs individual full-resolution regeneration, not cropping. This is the "commissioned art" category already agreed to defer until there are real users.
- **Nav icons** (section 1: Home/Workouts/Calendar/Timer/Hero/Profile) — checked the actual bottom nav (`.nav-btn`) and found it's built from inline `stroke="currentColor"` SVGs at **18×18px** that already re-theme perfectly (color follows `.nav-btn.active{color:var(--gold)}` automatically) and stay crisp at any size since they're vector. Swapping to the sheet's heavy, textured, detailed 3D-badge-style icons at that same tiny size would very likely read as cluttered/muddy rather than premium — fine detail doesn't survive being shrunk that far, and a static-color bitmap loses the free perfect-recolor the SVGs already have. **Judgment call: skipped, not attempted.** If this is wanted anyway, the honest path is the CSS `mask-image` technique (silhouette the icon, recolor via `background-color:currentColor`) rather than a direct bitmap swap — that preserves recoloring but loses the carved-metal texture look, so it's a real trade-off either way, not a strict upgrade. Flagged for the user to decide rather than picked unilaterally.
- **Remaining achievement medallions** (section 5) — only used 1 of 6 (First Workout, as a generic flourish). The other 5 are more specific (Dedication="10", Calorie Destroyer, Hydration Hero, Arena Victor, Boss Slayer) and only 6 exist vs. ~45 real badges in the app — using more of them means either deciding which real badges they map to, or generating more variants.
- **Bar end-caps as bitmap** — attempted, abandoned. Every bar sample in the sheet has its fill baked in from the left edge, so there was no clean "empty metal" region to extract a reusable end-cap from. CSS-drawn diamonds were a better trade for the effort.
- **Remaining small UI icons** (section 9: envelope, funnel, chart, bell) — no clean integration point found yet (no notification system, no filter UI in an obvious spot). Worth revisiting if those features get built.
- **Exercise-picker search** (`hm-exp-search`) — no icon slot in its current layout; a layout change (not just an asset swap) needed to add one.

## Extraction pipeline (if redoing/extending)

`_crops/extract.ps1` — auto-detects a tight bounding box within a generous hand-picked window (luminance threshold), then chroma-keys near-black to transparent with a soft ramp (avoids hard jaggy edges). Generous windows first, tighten based on what bleeds in from neighbors, 2-3 iterations typically gets a clean crop. `_crops/` and `new_art.png`/`_ui-kit-source.png` are source working files, not shipped assets — the real deliverables are in `assets/ui/`.

## How to preview
